**Data flow per step:** `ExplorationAgent` reads `GameState` from `IEmulatorClient` → `StatePreprocessorService` turns it into a `Tensor` → `DQNTrainer.SelectAction` picks an `ActionType` (epsilon-greedy over `PokeDQN` output) → `ActionExecutor` sends the button press through `SocketProtocol`/`ConnectionManager` to the Lua bridge → new `GameState` is read → `RewardCalculatorService` computes a reward → a `ModelExperience` is stored via `IExperienceRepository` (Redis, prioritized) → periodically `DQNTrainer.TrainStepWithPriorities` samples a batch and updates the network, priorities, and the shared `AdaptiveLRScheduler`/`ParameterServer` state in Redis.

## 3. Project-by-project detail

### `PokemonRedRL.Agent` (entry point)
| File | Purpose |
|---|---|
| [Program.cs](../src/PokemonRedRL.Agent/Program.cs) | `Main`: builds a generic `Host` with DI (logging, `NetworkConfigFactory`, `ParameterServer`, `RedisConfig`, `ConnectionMultiplexer` to `localhost:6379`, `AdaptiveLRScheduler`, `RedisMaintenanceService` hosted service, per-agent scoped services). Parses optional `--port <n>`/`--agent-index <n>` CLI args; if `--port` is given, runs a **single** `ExplorationAgent` bound directly to that port (`RunSingleAgentAsync`, bypasses `NetworkConfigFactory` scanning) — this is the mode `PokemonRedRL.ControlPanel` launches one process per emulator slot with. With no `--port`, falls back to the legacy `RunLegacyMultiAgentAsync`: `NUMBER_OF_AGENTS` (currently 10) long-running tasks in one process, each with its own DI scope + `ExplorationAgent`, ports discovered via `NetworkConfigFactory` scanning, looping `RunEpisodeAsync` until cancelled. |
| [ExplorationAgent.cs](../src/PokemonRedRL.Agent/ExplorationAgent.cs) | Core episode loop: loads an initial prioritized/random batch from Redis, then for each step gets the current `GameState`, preprocesses it to a tensor, selects an action via `DQNTrainer.SelectAction` (epsilon-greedy, decaying `ε` from 1.0 to 0.01), executes it via `ActionExecutor`, computes reward via `RewardCalculatorService`, stores a `ModelExperience`, and periodically triggers a training step (`TrainWithAutoBatch`, every 500 steps: 70% prioritized / 30% random sample). Tracks `visitedLocations` for novelty bonuses. Input tensor size `14`, action space size `6` (`ActionType`). `LogProgress` prints both a human-readable line and a machine-parseable `STATUS map=... x=... y=... action=... reward=... total=... epsilon=...` line (InvariantCulture-formatted) consumed by `PokemonRedRL.ControlPanel`'s `AgentTelemetryParser`. |
| [appsettings.json](../src/PokemonRedRL.Agent/appsettings.json) | Logging configuration (console formatter, per-category log levels). |

### `PokemonRedRL.Core` (emulator I/O + RL services interfaces)
| Folder/File | Purpose |
|---|---|
| `Emulator/ConnectionManager.cs` | Owns a `TcpClient`/`NetworkStream`, `EnsureConnected()` retries connecting per `NetworkConfig` (host/port/retries/delay), throws `TimeoutException` after max retries. |
| `Emulator/SocketProtocol.cs` | `SendCommand(string)`: writes ASCII command + `\n`, reads until a `\n`-terminated response, returns it trimmed. This is the entire wire protocol — a new command must be added here **and** handled in the Lua script. |
| `Emulator/MGBAEmulatorClient.cs` | Implements `IEmulatorClient`; translates protocol responses into `GameStateResponse`/`GameState`, exposes `CurrentPort`. |
| `Helpers/ActionExecutor.cs` | Maps `ActionType` → button command(s) sent through `SocketProtocol`; `GetActionName` for logging. |
| `Helpers/NetworkConfig.cs`, `NetworkConfigFactory.cs` | Per-agent network settings (host, port, retry policy); factory likely assigns distinct ports per agent instance. |
| `Interfaces/IEmulatorClient.cs`, `IRewardCalculatorService.cs`, `IStatePreprocessorService.cs` | Contracts implemented in `Services/`/`Emulator/`. |
| `Services/RewardCalculatorService.cs` | Computes step reward from `GameState` + `isNewLocation` flag (novelty bonus, HP/battle/badge signals). |
| `Services/StatePreprocessorService.cs` | Converts `GameState` → TorchSharp `Tensor` (`[HP, MapID, X, Y, Direction, Badges, InTrainerBattle, Money, PartyLevels[0-5]]`, size 14; namespace `PokemonRedRL.Core.Services`, matching its project). |

### `PokemonRedRL.Models` (RL core + Redis-backed persistence)
| Folder/File | Purpose |
|---|---|
| `Configuration/RedisConfig.cs` | Redis connection settings. |
| `Experience/ModelExperience.cs` | `(State, Action, Reward, NextState, Weight, Id)` experience record used throughout replay/training. |
| `Interfaces/IExperienceRepository.cs` | `AddAsync`, `SampleAsync`, `SamplePrioritizedAsync`, `UpdatePrioritiesAsync` contract (namespace `PokemonRedRL.Models.Interfaces`). |
| `ReinforcementLearning/PokeDQN.cs` | TorchSharp `Module`: `Linear(input,128) → ReLU → Linear(128,64) → ReLU → Linear(64,output)`. |
| `ReinforcementLearning/DQNTrainer.cs` | Wraps `PokeDQN` (+ likely a target network), `SelectAction` (epsilon-greedy), `TrainStepWithPriorities` (TD-error-based prioritized training), `TrainStepCount`, `TrackEpisodeReward`. |
| `ReinforcementLearning/AdaptiveLRScheduler.cs` | Adjusts learning rate based on a reward window; persists/loads state (`LoadStateAsync`) via `ParameterServer`/Redis so all agents share it. |
| `Services/ExperienceReplay.cs`, `SumTree.cs` | Prioritized experience replay buffer backed by a sum-tree for O(log n) sampling. |
| `Services/MemoryCache.cs` | In-process cache layer (reduces Redis round-trips). |
| `Services/ParameterServer.cs` | Shared hyperparameter/state store across concurrent agents (Redis-backed). |
| `Services/RedisExperienceRepository.cs` | `IExperienceRepository` implementation over Redis (serializes `ModelExperience`, prioritized sampling; namespace `PokemonRedRL.Models.Services`). |
| `Services/RedisMaintenanceService.cs` | `BackgroundService` — periodic Redis housekeeping (e.g., trimming/expiry) registered via `AddHostedService`. |

### `PokemonRedRL.ControlPanel` (WPF desktop control panel)

Implements Task 2b ([docs/tasks/automated-mgba-launch-and-fast-forward.md](tasks/automated-mgba-launch-and-fast-forward.md)). References `PokemonRedRL.Core` (reuses the `ping`/`pong` bridge protocol) and `PokemonRedRL.Utils` only — deliberately not `PokemonRedRL.DAL`/`Models`, since it doesn't need `GameState`/TorchSharp/Redis directly (it launches `PokemonRedRL.Agent` as a separate process instead).

| Folder/File | Purpose |
|---|---|
| `App.xaml.cs` | Manual composition root (`OnStartup`): constructs `RunManifestService`, `AgentProcessManager`, `EmulatorPingProbe`, `PreviewCaptureService`, `WindowEnumerationService`, and `MainViewModel`, then shows `MainWindow`. |
| `MainWindow.xaml(.cs)` | Session settings form (ROM path, agent count, base port, run directory, speed profile), paginated 3x3 tile `ListBox` (`CurrentPageTiles`), pagination buttons, and a selected-tile log panel. Code-behind only handles the per-tile "Attach window..." click (opens `WindowPickerDialog`) — everything else is bound. |
| `Models/RunManifest.cs`, `AgentSlot.cs`, `Enums.cs` | Persisted run shape: `RunManifest { RunId, CreatedUtc, RomPath, LaunchMode, SpeedProfile, RunDirectory, Agents }`, `AgentSlot { Index, Port, EmulatorProcessId, AgentProcessId, WindowHandle, RuntimeDirectory, Status, LastPingUtc }`, plus `LaunchMode`/`SpeedProfile`/`AgentSlotStatus`/`AgentConnectionState` enums. |
| `Services/RunManifestService.cs` | Creates `runs/<timestamp>/manifest.json` plus one `agent-<i>/` runtime directory per slot; saves/loads via `System.Text.Json`. |
| `Services/EmulatorPingProbe.cs` | Probes one *known* port (pre-assigned per slot) with the same `ping\n`→`pong` handshake as `NetworkConfigFactory` — no range scanning, since manual-attach mode makes ports 1:1 with slots. |
| `Services/WindowEnumerationService.cs` | `EnumWindows`/`GetWindowThreadProcessId` P/Invoke to list candidate mGBA top-level windows; deliberately does **not** auto-correlate a window to a port/slot (see remarks — avoids the "misleading dashboard" risk). |
| `Services/PreviewCaptureService.cs` | `PrintWindow`-based single-frame capture of a given `HWND` → WPF `BitmapSource`, per the Task 1 frame-capture spike decision. |
| `Services/AgentProcessManager.cs` | Launches one `PokemonRedRL.Agent.dll --port <n> --agent-index <n>` process per slot (locates the built DLL by walking up to `PokemonRedRL.sln`), streams stdout/stderr, raises `LogLineReceived`/`AgentExited`. Only ever starts/stops processes it itself launched — no global process kill. |
| `Services/AgentTelemetryParser.cs` | Parses the `STATUS ...` line `ExplorationAgent.LogProgress` emits into an `AgentTelemetry` record (InvariantCulture numeric parsing). |
| `ViewModels/MainViewModel.cs` | Owns session settings, `AllTiles`/`CurrentPageTiles` (9-per-page paging), Start/Stop/Next/Previous commands, a 10 FPS preview `DispatcherTimer` (current page only), and a 2 s ping `DispatcherTimer` (all slots). |
| `ViewModels/AgentTileViewModel.cs` | Per-slot bindable state: connection state, preview image, window handle, map/x/y/action/reward/total/epsilon, error message, capped (500-line) log buffer. |
| `ViewModels/ViewModelBase.cs`, `RelayCommand.cs` | Minimal hand-rolled `INotifyPropertyChanged` base + `ICommand` (no external MVVM toolkit dependency added). |
| `Views/WindowPickerDialog.xaml(.cs)` | Modal dialog listing `WindowEnumerationService` candidates so the user explicitly picks which mGBA window belongs to a tile. |

**Known limitation (recorded, not silently missing):** only `LaunchMode.ManualAttach` is functional — `AutomatedLaunch` exists in the model/enum but is not wired to any launcher, because neither the vendored mGBA 0.10.5 binary nor a locally-built upstream binary support the needed `--script` automation in this workspace (see the plan's Step 3 finding). Similarly, `SpeedProfile.Accelerated` is manifest metadata only; the control panel cannot enforce mGBA fast-forward (Step 10 finding) — the UI surfaces this as a tooltip rather than pretending to control it.

## 5. Known gaps / follow-ups worth tracking

- No automated test project exists yet for any of the 5 projects — consider adding an `xUnit` test project when adding non-trivial logic (esp. `DQNTrainer`, `RewardCalculatorService`, `StatePreprocessorService`).
- No CI workflow under `.github/workflows/` — build/verification is manual (`dotnet build src/PokemonRedRL.sln`).
- Redis connection string (`localhost:6379`) and mGBA host/ports are hardcoded in `Program.cs`/`RedisConfig`/`NetworkConfigFactory` rather than externalized to `appsettings.json` — worth revisiting if the agent needs to run against non-local infra.
- `PokemonRedRL.ControlPanel` is manual-attach-only for now (see §3.5) — automated mGBA launch, real 1/3/10-instance scale verification, and enforced speed profiles are recorded, tracked gaps rather than implemented features.
- See [docs/PROJECT_OVERVIEW.md](PROJECT_OVERVIEW.md) §6 for additional design-level gaps (reward-shaping bug candidate, diverged Lua scripts, duplicate DI registration, apparently-unused local replay classes).
